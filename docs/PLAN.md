# План реализации: PDF-чертёж тары → 3D-модель для Blender (десктопное приложение)

## Цель

Пользователь перетаскивает в окно приложения PDF-чертёж стеклянной тары (бутылки, декантеры) от заказчика или стекольного завода. Приложение строит модель вращением реального контура из векторного PDF и показывает результат: наложение найденного контура на чертёж, таблицу «по чертежу → в модели», 3D-превью и рендер. После проверки пользователь сохраняет `.blend` (и при необходимости `.glb`).

Параметрический шаблон и генеративный AI для построения геометрии не используются.

Поток заказов небольшой. Точность и проверяемость важнее скорости и автоматизма. Каждую модель перед отдачей смотрит человек, и приложение строится вокруг этого шага: если что-то определилось неверно, пользователь поправляет это в интерфейсе, а не в коде.

## Эталонный входной файл

`tests/fixtures/BUTELIS_WISKEY_700ml_Cork.pdf` — чертёж AB «Panevėžio stiklas», B70-0089, бутылка для виски на 700 мл под пробку (Cork).

Что о нём уже известно (проверено через pdfplumber):

- 1 страница A2 (1684×1191 pt ≈ 594×420 мм), векторная, текст извлекается.
- Виды: FRONT VIEW (подписан 1:1), LEFT VIEW, BOTTOM VIEW, выноска B (2:1) с горловиной, выноска A (3:1) с пупырышками на дне, развёртки гравировок, штамп в правом нижнем углу.
- Ось вращения на FRONT VIEW — штрихпунктирная вертикаль, x ≈ 117.2 мм от левого края листа.
- Основной контур ≈ 0.84 pt, размерные и выносные линии ≈ 0.72 pt.
- **Подписанный масштаб «1:1» неверен:** высота контура на листе ≈ 250.6 мм при размере 246.0, коэффициент ≈ 0.9815. Масштаб всегда калибруется по размерам.
- Контрольные размеры: общая высота 246.0±1.6, корпус Ø88.3±1.6, дно Ø73.0±1.4, горловина Ø27.5 / Ø31.0, внутренний диаметр горла Ø18.7±0.3.
- Штамп: 700 мл ±7, полная ёмкость ~720 мл, вес ~500 г, стекло Flint, высота налива от верха 53 мм, горловина Cork / SPEC.
- Грубый прототип (огибающая по точкам) после калибровки дал корпус Ø88.4 и дно Ø73.1.

**Проверить первым делом:** есть ли на листе разрез или полуразрез (в основном виде или в выноске B). Если есть, внутренний профиль и толщина стенки берутся прямо с чертежа, и оценка стенки по весу (этап 6) становится только проверкой.

## Архитектура

Три слоя, каждый можно запускать и тестировать отдельно:

```
┌──────────────────────────────┐
│  GUI (PySide6)                │  drag-n-drop, просмотр, правки, сохранение
└──────────────┬───────────────┘
               │ вызывает как библиотеку, в фоновом потоке
┌──────────────▼───────────────┐
│  core (чистый Python)         │  PDF → контур → калибровка → стенка → profile.json + report
└──────────────┬───────────────┘
               │ subprocess + JSON-файл
┌──────────────▼───────────────┐
│  Blender (headless)           │  profile.json → .blend, .glb, preview.png
└──────────────────────────────┘
```

Правила:

- **core не знает про GUI**, у него есть CLI (`bottle3d run in.pdf --out out/`). Всё, что делает приложение, можно повторить из командной строки и из тестов.
- **core и Blender общаются только через `profile.json`.** Внутри Blender только `bpy`, `bmesh`, `mathutils` и stdlib.
- **Все пользовательские правки сохраняются в `job.yaml`** рядом с результатом (ось, bbox вида, толщина контура, толщина дна, переопределённые размеры). Повторный запуск с тем же `job.yaml` даёт тот же результат.
- **Blender — внешний процесс.** Приложение ищет установленный Blender 4.2 LTS (стандартные пути, PATH, настройка в приложении) и проверяет версию при старте. Встраивать Blender в дистрибутив — отдельное решение после M4 (≈ 400 МБ и GPL, см. «Лицензии»).

## Стек

- Python 3.11+, `uv`
- **Векторы и текст PDF:** PyMuPDF или pdfplumber/pdfminer.six — выбор зависит от лицензии (см. ниже). Код извлечения прячется за интерфейсом `pdf/vectors.py`, чтобы библиотеку можно было заменить.
- `numpy`, `shapely` (offset профиля), `pydantic` v2 (схемы, `job.yaml`, `profile.json`)
- **GUI:** PySide6 (LGPL). Просмотр чертежа с наложением — `QGraphicsView`. 3D-превью — сначала просто PNG-рендер из Blender; интерактивный просмотр `.glb` (QtWebEngine + three.js или pyvista) — опционально.
- **Упаковка:** PyInstaller (или Briefcase), один установщик на ОС.
- **Blender 4.2 LTS** headless (`blender -b --factory-startup -P ...`), версия фиксируется.
- `pytest`, `ruff`
- `anthropic` SDK — **не в MVP**, см. этап 5.

## Лицензии (проверить до M0)

- **PyMuPDF — AGPL** (или коммерческая лицензия Artifex). Для внутреннего инструмента проблем нет. Если приложение отдаётся клиентам, нужно либо открыть код под AGPL, либо купить лицензию, либо использовать pdfplumber/pdfminer.six (MIT) или pypdfium2 (Apache/BSD). Прототип уже работал на pdfplumber, так что замена реальна.
- **Blender — GPL.** Запускать установленный Blender как отдельный процесс можно без последствий для лицензии приложения. Если Blender встраивать в дистрибутив, нужно выполнять условия GPL для самого Blender (исходники, текст лицензии).
- **PySide6 — LGPL**, для закрытого приложения подходит при динамической линковке (PyInstaller так и делает).

## Пайплайн core

### Этап 1. Извлечение векторов (`pdf/vectors.py`)

- Привести пути к списку `Segment(kind, points_mm, width_pt, dashed, color)`. Единицы — мм, ось Y вверх. `re` и `qu` разложить на отрезки.
- Поворот страницы: не полагаться на документацию, а проверить синтетическим PDF с `rotation=90`.
- Гистограмма толщин линий — отдельная функция, её же показывает GUI.
- Обработать и явно сообщить пользователю: страница без векторов (скан), текст в кривых, несколько страниц (выбор страницы в GUI), слои (OCG).

**Готово, когда:** на эталоне есть сегменты ≈ 0.84 и ≈ 0.72 pt и найдена штрихпунктирная вертикаль около x ≈ 117 мм; синтетический повёрнутый PDF даёт те же координаты, что и неповёрнутый.

### Этап 2. Ось и вид (`geometry/view_detect.py`)

Автоопределение — **подсказка**, которую пользователь подтверждает или поправляет в GUI одним кликом (выбрать ось, обвести вид рамкой). Поэтому эвристика может быть простой.

1. Кандидаты в оси — длинные вертикальные штриховые линии (один путь с `dashes` или цепочка коротких отрезков на одном x, допуск 0.2 мм).
2. Вокруг каждой собрать сегменты «контурной» толщины, оценить симметрию (отражение левой половины на правую).
3. Предложить кандидата с наибольшей оценкой «высота × симметричность».
4. **Сравнить контуры двух лучших видов** (обычно FRONT и LEFT). У круглой тары они совпадают. Если не совпадают — тара неосесимметрична, статус `needs_review` с понятным сообщением. Какой из двух совпадающих видов взять, не важно.

**Готово, когда:** на эталоне предложен FRONT или LEFT VIEW, их контуры совпадают в пределах 0.3 мм, а на синтетической «фляге» срабатывает предупреждение.

### Этап 3. Контур половины профиля (`geometry/contour.py`)

1. Взять сегменты контурной толщины в выбранном виде с x ≥ ось − ε.
2. Построить **внешнюю огибающую** r(z): для каждой высоты — максимальный r. Горизонтальные участки (торец венчика, дно) обрабатываются отдельно, на них r(z) многозначна.
3. Сразу **дискретизировать в полилинию** с ошибкой хорды ≤ 0.02 мм. Безье дальше не сохраняются: offset (этап 6) всё равно не даёт Безье, а полилиния упрощает всё остальное.
4. Дно: на MVP плоское, флаг в отчёте. Если пунт нарисован (в виде или выноске), брать его.
5. Результат — внешний контур от (0, z_дна) вверх до внешнего края торца венчика, в координатах листа (мм, до калибровки).

**Готово, когда:** контур непрерывный (разрывы < 0.05 мм), начинается на оси, на отладочном PNG ложится на чертёж; на синтетическом PDF совпадает с исходным профилем в пределах 0.05 мм.

### Этап 4. Калибровка масштаба (`geometry/calibrate.py`)

- Подписанный масштаб не используется.
- Опорные размеры: общая высота H, Ø корпуса D, Ø дна. Источник по приоритету: `job.yaml` (пользователь ввёл) → текст чертежа → ошибка «введите высоту вручную».
- **Масштаб считается по всем доступным размерам** (наименьшие квадраты), отдельно по X (диаметры) и Y (высоты). Если масштабы X и Y расходятся > 0.5 % или остатки больше допуска — `needs_review`.
- Лучше, чем просто искать число в тексте: найти размерную линию рядом с текстом «246.0» и брать масштаб из её длины. Это чисто геометрически и проверяемо. Делается в M3.
- Ожидаемо на эталоне: scale ≈ 0.98.

### Этап 5. Спецификация из штампа (`spec/`)

`BottleSpec`: `name, drawing_no, manufacturer, nominal_capacity_ml, brimful_capacity_ml, glass_weight_g, glass_colour, finish, fill_height_mm, overall_height_mm, body_diameter_mm, base_diameter_mm, neck_inner_diameter_mm, tolerances{...}`.

- `extract_rules.py`: регэкспы по билингвальным подписям штампа. На один завод этого достаточно.
- В GUI все поля спецификации видны и редактируемы; правки уходят в `job.yaml`.
- **LLM не в MVP.** Текст извлекается, человек всё равно смотрит каждую модель, а LLM в десктопном приложении добавляет ключ API у пользователя, сеть, недетерминизм и сложные тесты. Вернуться к этому после M7, если регэкспы на новых заводах будут ломаться.

### Этап 6. Стенка и объёмы (`geometry/wall.py`)

Если на чертеже есть разрез — внутренний профиль берётся оттуда, а расчёт ниже служит проверкой. Иначе:

- `V_outer` — интеграл π·r(z)²·dz по полилинии.
- **Главная проверка внешнего контура:** `V_outer ≈ brimful + glass_weight / 2.5` (на эталоне ≈ 720 + 200 = 920 см³), допуск ±3 %. Это проверяет контур и калибровку, а **не** толщину стенки: при любом распределении стекла `V_inner = V_outer − V_glass`.
- **Как стекло делится между стенкой и дном, из штампа не определяется.** Поэтому толщина дна `t_base` — явный параметр с умолчанием из профиля завода (для тяжёлых бутылок под виски 8–15 мм), видимый и редактируемый в GUI. Толщина стенки t подбирается бисекцией при заданном `t_base`, чтобы объём стекла совпал с весом.
- Внутренний профиль строится через `shapely`: полигон половины сечения → `buffer(-t)`. Это корректно обрабатывает вогнутые переходы (плечо, венчик), где наивный offset по нормали самопересекается.
- Горло внутри — по `neck_inner_diameter_mm` (Ø18.7), а не по смещению.
- **Вторая проверка — высота налива:** внутренний объём ниже отметки «53 мм от верха» ≈ номиналу 700 мл (±1 %). Проверяет внутренний профиль горла.
- t вне 1–8 мм — `needs_review`.

### Этап 7. `profile.json` — контракт core ↔ Blender

```json
{
  "version": 1,
  "units": "m",
  "section": [[r, z], ...],
  "material": {"glass_colour": "Flint"},
  "render": {"engine": "EEVEE", "resolution": 1024},
  "meta": {"source_pdf": "...", "pdf_sha256": "...", "tool_version": "...", "scale": 0.9815}
}
```

`section` — одна незамкнутая полилиния с обоими концами на оси: (0, z_дна_снаружи) → вверх по внешнему контуру → торец венчика → вниз по внутреннему → (0, z_дна_внутри). Точки на оси имеют ровно r = 0. Вращение такой линии даёт замкнутую поверхность.

### Этап 8. Сборка в Blender (`blender/build_bottle.py`)

Запуск: `blender -b --factory-startup -P blender/build_bottle.py -- profile.json out/ [--glb] [--preview]`

1. **Геометрия в метрах** (высота 0.246), `scale_length = 1`, `length_unit = 'MILLIMETERS'` только для отображения. Не задавать геометрию в мм с `scale_length = 0.001`: Cycles (свет, volume absorption), клиппинг камеры и экспорт glTF считают BU метрами, и бутылка получится высотой 246 м.
2. Меш строится напрямую: полилиния → `bmesh.ops.spin` на 360°, 128 шагов → слияние вершин на оси и шва → пересчёт нормалей.
3. Сглаживание: `shade_smooth_by_angle` (в 4.1+ `use_auto_smooth` убран).
4. Материал (`materials.py`): Principled BSDF, Transmission 1.0, IOR 1.52, Roughness 0.02, цвет по таблице (Flint, Green, Antique Green, Amber, UVAG…).
5. Превью: камера с автокадрированием по bbox, студийный фон. По умолчанию EEVEE (быстро, нужен GPU), Cycles 64 samples + denoise — по кнопке «Финальный рендер».
6. Экспорт `.glb` по флагу.

**Готово, когда:** `.blend` открывается, габариты совпадают со спецификацией (246 ±0.5 мм, Ø88.3 ±0.5 мм), меш manifold, **объём меша (`bmesh` `calc_volume`) совпадает с V_glass ±1 %** — это заодно ловит вывернутые нормали внутренней поверхности.

### Этап 9. Валидация и отчёт (`validate.py`)

`report.json` (для GUI) и `report.md` (для отдачи):
- таблица «по чертежу → в модели» для опорных размеров;
- масштаб X/Y, остатки калибровки, симметрия, совпадение видов, разрывы контура;
- объёмы: внешний, стекла, внутренний, проверка налива;
- толщина стенки и дна (и откуда взята: разрез, расчёт, умолчание, ручной ввод);
- предупреждения: плоское дно, не смоделировано (гравировка, пупырышки, dot code);
- итог: `ok` / `needs_review` со списком причин.

## Десктопное приложение (`app/`)

### Сценарий пользователя

1. **Перетащить PDF** в окно (или «Открыть…»). Несколько страниц — выбрать страницу.
2. **Экран чертежа:** чертёж с наложением найденной оси, рамки вида и контура. Если неверно — кликнуть по правильной оси, обвести вид рамкой, выбрать толщину контура из гистограммы. Пересчёт идёт сразу.
3. **Экран спецификации и отчёта:** поля штампа (редактируемые), таблица сверки, толщина дна, статус `ok` / `needs_review` с причинами, подсвеченными красным.
4. **Экран превью:** PNG-рендер из Blender (позже — вращаемая 3D-модель).
5. **Сохранить:** папка с `.blend`, `.glb`, `preview.png`, `report.md`, `job.yaml`. Повторное открытие `job.yaml` восстанавливает все правки.

### Технические требования

- Пайплайн core и Blender работают **в фоне** (QThread / отдельный процесс): прогресс по этапам, кнопка «Отмена», таймаут на Blender.
- **Поиск Blender** при первом запуске: стандартные пути установки на ОС, PATH, ручной выбор в настройках. Проверка версии (`blender --version`). Без Blender приложение всё равно показывает контур и отчёт, но не строит `.blend`.
- Ошибки — человеческими словами («В PDF нет векторной графики — похоже на скан»), полный лог — в файл и по кнопке «Скопировать для поддержки».
- Скрипты Blender (`blender/*.py`) поставляются внутри приложения как ресурсы и передаются в `-P` по абсолютному пути.
- Пути с кириллицей и пробелами — отдельный тест (Windows особенно).

### Упаковка

- PyInstaller, установщик на каждую целевую ОС. Проверить, что PyMuPDF/pdfplumber, shapely (GEOS) и PySide6 корректно собираются.
- macOS: подпись и нотаризация, иначе Gatekeeper не даст запустить. Windows: подпись желательна (SmartScreen).
- Сборка установщиков в CI (GitHub Actions на runner'ах нужных ОС).

## Тесты (минимум)

- **Синтетические PDF** (генератор в `tests/synthetic/`): известный профиль, известный масштаб, поворот страницы 0/90, разные толщины линий, «фляга» без осевой симметрии. Это единственная точная истина для контура и калибровки.
- `test_vectors`: на эталоне ≥ 2 толщины, штриховая вертикаль x ≈ 117 мм; повёрнутый синтетический PDF даёт те же координаты.
- `test_view_detect`: на эталоне FRONT/LEFT совпадают; на «фляге» — `needs_review`.
- `test_contour`: непрерывность, начало на оси; на синтетике отклонение ≤ 0.05 мм; на эталоне Ø корпуса 88.3 ±0.5, Ø дна 73.0 ±0.5 после калибровки.
- `test_calibrate`: scale ∈ [0.975, 0.99], масштабы X и Y совпадают.
- `test_wall`: на цилиндре и конусе численный объём совпадает с аналитикой < 0.1 %; offset без самопересечений на профиле с вогнутым плечом.
- `test_spec_rules`: из эталона извлекаются 700 мл, ~720 мл, ~500 г, Flint, B70-0089.
- `test_job_roundtrip`: `job.yaml` → результат → тот же `job.yaml` → тот же `profile.json` (детерминизм).
- `test_blender_e2e` (`@pytest.mark.blender`): габариты, manifold, объём меша ≈ V_glass.
- `test_app_smoke` (pytest-qt): запуск окна, загрузка эталона без GUI-взаимодействия, сохранение результата; пути с кириллицей и пробелами.

## Риски и открытые вопросы

- **Признаки контура у каждого завода свои.** Поэтому ручная правка в GUI — основной путь, а автоопределение — подсказка.
- **Подписанный масштаб ненадёжен** — только калибровка.
- **Неосесимметричная тара** (фигурные декантеры, фляги) вращением не строится. Ловится сравнением двух видов, отдаётся моделлеру.
- **Распределение стекла между стенкой и дном не определяется штампом.** Без разреза на чертеже толщина дна — допущение, и в отчёте это видно.
- **Зависимость от установленного Blender** у пользователя: версия, путь, GPU для EEVEE. Без Blender приложение должно оставаться полезным (контур и отчёт).
- **Лицензии:** PyMuPDF (AGPL) и встраивание Blender (GPL) при раздаче клиентам.
- **Упаковка** (PyInstaller + PySide6 + GEOS + PDF-библиотека, подпись на macOS) часто занимает больше времени, чем ожидается. Поэтому первая сборка уже в M2.
